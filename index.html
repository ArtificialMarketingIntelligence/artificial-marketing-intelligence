THE CREATION FLOW

From brief to final export

The intended production workflow. The current page implements the setup UI and local preview; the server-side rendering pipeline must be connected.

1
Upload and brief

Validate photos and source clips, store assets privately, and build a campaign brief from the selected product, tone, platform and CTA.

2
Generate and render

Backend creates a scene plan, requests AI video clips and voiceover, mixes licensed music, assembles captions, and renders the final timeline.

3
Preview and download

Poll job status, show render progress, preview the final MP4, and provide a signed download URL plus an optional SRT caption file.

⚙ Developer integration status — transparent by designThis HTML prototype has a working local form, file selection, asset list, aspect-ratio controls, and responsive mock preview. It does not call an AI service, upload selected assets, synthesize audio, burn captions into a video, or produce a rendered MP4. Those capabilities need a backend, provider API key(s), storage, and a video-rendering pipeline. The generate button will show this status rather than pretending a render succeeded.

Recommended backend contract

Use a server-side job API so provider keys never appear in browser JavaScript.

POST /api/assets

Receive files, validate MIME type/size, scan them, store in private object storage, and return asset IDs.

POST /api/video-jobs

Accept campaign brief, asset IDs, duration, aspect ratio, captions and audio options. Return a job ID immediately.

GET /api/video-jobs/:id

Return queued / generating / rendering / complete / failed, progress, preview URL, final MP4 URL, SRT URL, and safe error details.

Production essentials: provider credentials stored as server secrets; job queue and retries; signed asset/download URLs; licensed music; user consent for uploaded media; content moderation; cost limits; retention/deletion controls; and render-failure handling.
